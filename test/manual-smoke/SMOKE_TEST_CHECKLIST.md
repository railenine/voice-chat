# 🧪 RVxis E2E & Manual Smoke Test Checklist

Данный чеклист предназначен для регулярной ручной приёмки критических сценариев перед выпуском релизов.

---

### Сценарий 1. Два клиента в одной комнате (P2P Audio Mesh)
1. **Запуск:**
   - Запустить десктопное приложение `RVxis.exe` (Клиент 1).
   - Открыть в браузере `http://localhost:3000` (Клиент 2).
2. **Создание комнаты:**
   - Клиент 1 нажимает «Создать комнату», копирует 6-значный код (например, `K9X2M4`).
   - Клиент 2 вводит код комнаты в поле ввода и нажимает «Войти».
3. **Проверка:**
   - [ ] Оба клиента видят карточки друг друга с корректными никнеймами.
   - [ ] Бейдж участников вверху отображает `Участники (2/12)`.
   - [ ] При разговоре в микрофон загорается зелёный индикатор активности речи (`speaking`).

---

### Сценарий 2. Микрофон, заглушение звука и ползунки громкости
1. **Mute микрофона:**
   - Нажать хоткей (по умолчанию `Ё / \``) или кнопку микрофона на панели.
   - [ ] Иконка переходит в красное перечёркнутое состояние.
   - [ ] Второй участник видит индикатор «Muted» на карточке собеседника.
2. **Deafen (заглушение звука):**
   - Нажать хоткей `\` (Backslash) или кнопку наушников.
   - [ ] Звук входящих участников отключается.
   - [ ] Микрофон автоматически мьютится.
   - [ ] При снятии Deafen микрофон возвращается в предыдущее состояние.
3. **Регулировка индивидуальной громкости:**
   - Изменить ползунок громкости собеседника (от 0% до 200%).
   - [ ] Значение сохраняется в `localStorage` и не сбрасывается при смене никнейма.

---

### Сценарий 3. Реконнект и устойчивость к разрывам сети
1. **Имитация разрыва:**
   - На сервере или в браузере кратковременно отключить сеть (DevTools -> Offline).
   - [ ] Вверху появляется жёлтый баннер «Переподключение... (попытка 1)».
   - [ ] Таймер экспоненциального/линейного backoff плавно повторяет попытки (до 5000 мс).
2. **Восстановление:**
   - Включить сеть обратно (DevTools -> Online).
   - [ ] Появляется зелёный тост «Подключено ✓».
   - [ ] Голосовой канал и пиры восстанавливаются без дублирования карточек.

---

### Сценарий 4. Демонстрация экрана (Screen Sharing)
1. **Проверка прав:**
   - На мобильном устройстве/эмуляции кнопка демонстрации должна быть недоступна или заблокирована.
   - На десктопе нажать кнопку трансляции экрана.
2. **Трансляция:**
   - Выбрать окно или весь экран.
   - [ ] У собеседника открывается видеопоток без задержек.
   - [ ] При повторном клике трансляция завершается корректно.

---

### Сценарий 5. Окно и процесс обновления (Update UI & Room Protection)
1. **Проверка в лобби:**
   - При наличии новой версии в `latest.json` (например, `0.1.13`) в заголовке окна видна зелёная кнопка «Обновление».
   - Клик по кнопке открывает диалог обновления со списком изменений.
2. **Room Protection (защита активного звонка):**
   - Войти в активную комнату.
   - [ ] Автоматическое всплывающее окно обновления НЕ прерывает разговор.
   - [ ] В TitleBar остаётся доступна кнопка «Обновление».
   - [ ] При ручном клике на кнопку внутри комнаты отображается янтарное предупреждение:
     *«Внимание: Вы находитесь в голосовом канале. Установка обновления разорвет активное соединение и перезапустит приложение»*.
